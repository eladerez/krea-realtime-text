Krea Realtime 14B · realtime text bench

How Krea draws the text you type, and where our changes act

Krea makes video in blocks of 12 frames (3.8 s). Each block is drawn from noise in 4 steps through a stack of 40 transformer blocks. The typed text can reach those blocks two ways: through the prompt, and through the memory of recent frames. Our writer puts the text into the memory, the lock keeps it there, and the LoRA teaches the model to copy what the memory shows.

Research · feature probe

Where the digit lives inside Krea

We recorded the hidden state at each digit's own position on the display, at blocks 10, 20, 30 and 39 and at each of the 4 steps, and asked a simple classifier which digit it holds. It was tested on numbers it never saw.

t 1000t 909t 714t 0
block 10 23% 52% 73% 81%
block 20 45% 61% 70% 68%
block 30 30% 46% 56% 54%
block 39 31% 43% 52% 51%
  • Chance is 2%. The same test on the keypad below the display gets 4–6%, so the digit is held at its own place, not spread over the frame.
  • It is strongest in blocks 10–20, and already there at the first step, while the frame is still noise. So it comes from the memory and the prompt.
  • All five positions share one digit code: a probe trained on the left three reads the right two at 82%.
  • When Krea drew a wrong digit, the hidden state held the wrong (drawn) digit 57% of the time and the typed one 25% (44 cases). The error is inside the model before the image is decoded.

Measured on calculator digits only (data/scores/probe_digits.json). Letters were not probed.

Training · LoRA

Where the LoRA sits and what it changed

  • Where: small adapters on self-attention (the fused q, k, v projection and the output o) in all 40 blocks. Rank 16, 19.7M parameters, 0.14% of the model. Cross-attention is untouched.
  • Trained on: Krea's own frames. Where a frame of a block drew the number right, its display was copied onto the wrong frames, and the model learned to produce that. The display counts fully in the loss, the rest of the frame at 0.1.
  • Shipped: merged into the weights (98% of the update survives bf16), so it costs no time: 3.45–3.65 s per block vs 3.75–3.86 s for base.

How it helps: self-attention is where the display's tokens read the memory. The LoRA makes them copy and hold what the memory shows, so a block no longer drifts from 23476 to 29476. With the prompt alone (nothing written into memory), v2 does not switch: it holds the old number in 27–57% of frames, base in 4–28%. It learned to keep the memory's text, not to read the prompt.

With the general writer putting the text into memory, base Krea already keeps it on most surfaces, letters included. v2, trained only on calculator digits, adds on three of five and holds the scene steadier: on the door sign base's camera dives into the sign and the scene breaks up, while v2 stays put with every word right.

The LoRA saw only calculator digits; cross-attention, the path that reads the prompt, has no adapter yet.
